OBJETIVO GERAL
--------------
Robot autônomo (palmares_bot) realiza docking na estação de carregamento
(charging_dock) usando ArUco ID=771, comando: "vai pra dock"
Stack: ROS2 Jazzy + Gazebo Harmonic + Nav2 + slam_toolbox + opennav_docking

[5] STAGING TOLERÂNCIA CORRIGIDA
    - dock_prestaging_tolerance aumentado de 0.6m para 1.5m.

================================================================================
COMO INICIAR E EXECUTAR O DOCKING
================================================================================

# Terminal 1 — antes de cada sessão (mata processos anteriores):
pkill -9 -f "ros2 launch sim_bot|gz sim|dock_pose|odom_to_tf|joint_state_pub|slam_toolbox|nav2|docking|twist_mux|robot_state" 2>/dev/null; sleep 3

# Terminal 1 — sobe tudo:
cd ~/sim_ws && source install/setup.bash && ros2 launch sim_bot palmares_bot.launch.py
# Aguarda ~30s para SLAM (t=5s), Nav2 (t=20s) e docking server (t=25s) subirem.

# Terminal 2 — confirma detecção (deve retornar pose):
source ~/sim_ws/install/setup.bash && ros2 topic echo /detected_dock_pose --once

# Terminal 2 — envia comando de docking:
source ~/sim_ws/install/setup.bash
ros2 action send_goal /dock_robot nav2_msgs/action/DockRobot \
  "{use_dock_id: true, dock_id: 'base_carregamento', navigate_to_staging_pose: true}"

================================================================================
O QUE AINDA FALTA / PENDÊNCIAS
================================================================================

[A] TESTE COMPLETO DE DOCKING COM MOVIMENTO REAL
    - O stack completo ainda não foi testado com o robô físico se movendo até a dock.
    - O docking server recebe a pose e controla o robô, mas o resultado final
      (robô para a 5cm da dock) não foi confirmado visualmente.
    - Rodar e observar no RViz/Gazebo GUI se o robô avança e para corretamente.
    - Se abortar com error_code=904 (FAILED_TO_DETECT_DOCK): verificar se
      /detected_dock_pose está publicando ANTES de enviar o goal de docking.
    - Se abortar com error_code=905 (FAILED_TO_CONTROL): ajustar docking_threshold
      (atualmente 0.05m, aumentar para 0.10m se oscilar).

[B] NAVEGAÇÃO AUTÔNOMA ATÉ A STAGING POSE (LONGO PRAZO)
    - Com navigate_to_staging_pose: true e robô longe da dock, o Nav2 precisa de
      um mapa SLAM maior para planejar a rota até (1.3, 0.0).
    - Fluxo real: robô explora ambiente primeiro (constrói mapa), depois recebe
      goal de docking. O dock_prestaging_tolerance=1.5m cobre o caso de spawn
      próximo à dock.
    - Se robô vier de longe: aumentar o dock_prestaging_tolerance para 0 e deixar
      Nav2 navegar usando o mapa já construído.

[C] LIDAR FALLBACK (FASE 2) NÃO TESTADO
    - dock_pose_estimator.py tem lógica para usar LiDAR quando ArUco some (< ~0.5m).
    - Nunca chegou a ser testado de perto o suficiente para ativar.
    - Parâmetro: aruco_timeout=1.5s, sector_half_deg=30.0.

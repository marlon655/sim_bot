SESSÃO 7 — 2026-06-15
================================================================================

MUDANÇAS DA SESSÃO 7:

  1. [REESCRITA] charging_manager.py — novo sistema orientado a tarefas com bateria

     ARQUITETURA NOVA (substitui o loop wander→dock):
       STARTUP → HOME_CHARGING (dock permanente = home)
       HOME_CHARGING: carrega sempre; aceita tarefa da fila se bat ≥ 40%
       Tarefa aceita → UNDOCKING → GOING_TO_TASK → EXECUTING_TASK → RETURNING_HOME
       Após tarefa:
         bat < 20% → retorna imediatamente (forçado)
         bat ≥ 20% + fila não vazia + bat ≥ 40% → executa próxima tarefa direto
         caso contrário → retorna para home

     FILA DE TAREFAS:
       - FIFO; tarefas publicadas nos tópicos sempre entram na fila
       - Processada automaticamente quando HOME_CHARGING + bat ≥ 40%
       - Se robô estiver em qualquer outro estado: fila acumula, aguarda retorno

     QUATRO TIPOS DE TAREFA:
       /task/goto_pose   geometry_msgs/PoseStamped  — vai ao ponto, espera 2 s
       /task/inspect     geometry_msgs/PoseStamped  — vai, espera 5 s (inspeção)
       /task/patrol      std_msgs/String            — patrulha rota "A", "B" ou "C"
       /task/deliver     geometry_msgs/PoseStamped  — vai, espera 3 s (entrega)

     BUGS CORRIGIDOS NA SESSÃO 7:
       - wait_for_server() removido de todos os callbacks (bloqueava o executor)
       - server_is_ready() não-bloqueante + retry via _once() em todos os action clients
       - DOCK_MAX_FAILS=4: contador de falhas de DockRobot (evita loop infinito)
       - Undocking simples: reverse cmd_vel (UNDOCK_SPEED=-0.15 m/s × 2.0s ≈ 30cm)
         em vez de UndockRobot action (mais confiável)
       - docking_threshold: 0.02 → 0.05 (5cm tolerância, evita DockRobot nunca declarar sucesso)

================================================================================
FLUXO ESPERADO (SESSÃO 8)
================================================================================

STARTUP (t=0–15 s):
  Robô estático em odom(0,0) = staging. Nav2 e docking server sobem.

t≈15 s → HOME_CHARGING automático:
  _autostart() → HOME_CHARGING (sem navegar — robô já está no staging)
  Bateria começa a carregar a 1%/s.

Quando HOME_CHARGING + bat ≥ 40% + tarefa na fila:
  [UNDOCKING] → [GOING_TO_TASK] → [EXECUTING_TASK] → [RETURNING_HOME]
  → [DOCKING]  (DockRobot navega até staging + abordagem precisa)
  → verifica alinhamento (y_err≤5cm, yaw≤10°)
  → [HOME_CHARGING]

Regras de bateria:
  bat ≥ 40% + fila → aceita tarefa
  bat < 20% após tarefa → retorna imediatamente
  bat ≤  5% durante tarefa → aborta e retorna
  HOME_CHARGING → carregando sempre

ATENÇÃO — LIÇÕES APRENDIDAS
================================================================================

- NÃO usar pkill dentro do launch file (mata o próprio processo)
- wait_for_server() em callbacks bloqueia o executor → usar server_is_ready() + _once()

- docking_threshold muito apertado (0.02) impede DockRobot de declarar sucesso
- Odom frame drift: spawn em (1,0) reduz distância de navegação (menos erro acumulado)
